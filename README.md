# KopiyochkaParser

каталог «копійочки» в postgresql, з термінала.

невеликий python-скрипт: збирає товари з сайту kopiyochka.ua (назва, категорія, ціна, стара ціна, залишок по місту) і записує їх у postgresql. зображення за бажанням стискаються в avif і кладуться в cloudflare r2. скрипт ходить у мережу (сайт і ajax «копійочки»): без цього він не працює.

лише код, без релізів. MIT.

## запуск

потрібні python 3.12 або новіший, [uv](https://docs.astral.sh/uv/) і postgresql. запускати з кореня репозиторію.

```sh
uv run dumper_kopiyochka.py --no-images --limit 20   # перевірка на 20 товарах
uv run dumper_kopiyochka.py                          # повний дамп з фото
uv run dumper_kopiyochka.py --no-images --recent 24  # пропустити свіжі
```

| ключ | що робить |
| --- | --- |
| `--no-images` | без зображень і без r2 |
| `--recent N` | пропустити товари, оновлені в базі за останні N годин |
| `--limit N` | лише перші N товарів, для перевірки |
| `--city` | місто, за замовчуванням хмельницький |

## що робить

1. створює таблицю `kopiyochka_products`, якщо її немає.
2. збирає адреси товарів із `sitemap_index.xml`.
3. для кожного товару бере сторінку (код, назва, зображення, категорія з «хлібних крихт»), потім ціну й залишок через ajax магазину для вибраного міста.
4. записує товар у базу; якщо нічого не змінилося, оновлює лише час перевірки. товар, якого немає в місті, пропускається.
5. наприкінці показує підсумок: нові, оновлені, без змін, фото, знижки від 50 %, немає в місті, помилки.

сторінки товарів беруться через `obscura` (у `PATH` або в `obscura/` поруч зі скриптом), якщо його немає, через звичайний http. одночасно обробляються 2 товари, між запитами пауза 1,5–3 с. на 429 і блокування wordfence скрипт чекає й повторює запит, до 5 разів.

## структура

| файл | що в ньому |
| --- | --- |
| `dumper_kopiyochka.py` | увесь скрипт: sitemap, сторінки, ajax, зображення, postgresql |
| `pyproject.toml`, `uv.lock` | залежності для uv |

## налаштування

локальний файл `.env` поруч зі скриптом (у репозиторій не входить):

```
DATABASE_URL=postgresql://user:pass@host:5432/db
R2_ACCESS_KEY=
R2_SECRET_KEY=
R2_ENDPOINT=
R2_BUCKET=
CDN_URL=
```

без `DATABASE_URL` скрипт не запускається. `R2_*` і `CDN_URL` потрібні лише для зображень; без них потрібен `--no-images`.

## обмеження

перевірено: запуск на 5 товарах без зображень, із записом у локальну базу postgresql.

не перевірено, тому не обіцяється:

- повний дамп усього каталогу
- зображення: стискання в avif і завантаження в r2
- робота через `obscura`
- інші міста, крім хмельницького
- автоматичних тестів немає

відомо:

- скрипт залежить від розмітки й ajax сайту: коли сайт зміниться, він може перестати працювати. у листопаді 2026 сайт перестав віддавати магазини в `city_items`, тепер вони в `map_items` для всіх міст; скрипт бере магазини потрібного міста звідти
- код товару, назва й категорія беруться з розмітки сторінки; якщо її змінять, товари почнуть потрапляти в помилки
