# kopiyochka parser

синхронізує каталог «копійочки» (kopiyochka.ua) у postgresql: назва, категорія, ціна, стара ціна, залишок по місту. зображення за бажанням стискаються в avif і кладуться в cloudflare r2.

## запуск

потрібні [uv](https://docs.astral.sh/uv/) і postgresql. таблиця `kopiyochka_products` створюється сама.

```
uv run dumper_kopiyochka.py --no-images --limit 20
uv run dumper_kopiyochka.py                # повний дамп з фото
uv run dumper_kopiyochka.py --no-images --recent 24
```

- `--no-images` — без r2
- `--recent N` — пропустити товари, оновлені за останні N годин
- `--limit N` — лише перші N товарів, для перевірки
- `--city` — місто, за замовчуванням хмельницький

сторінки товарів беруться через `obscura` (у `PATH` або в `obscura/` поруч), якщо його немає — через звичайний http. ціни й залишки — з ajax магазину. між запитами є паузи, паралельність — 2.

## .env

```
DATABASE_URL=postgresql://user:pass@host:5432/db
R2_ACCESS_KEY=
R2_SECRET_KEY=
R2_ENDPOINT=
R2_BUCKET=
CDN_URL=
```

`R2_*` і `CDN_URL` потрібні лише для зображень.

## про проєкт

частина lezneve. скрипт залежить від розмітки й ajax сайту: коли сайт зміниться, він може перестати працювати. у листопаді 2026 сайт перестав віддавати магазини в `city_items`, тепер вони в `map_items` для всіх міст; скрипт бере магазини потрібного міста звідти. товар, якого немає в місті, пропускається. перевірено на 6 товарах і локальній базі; повний дамп, зображення (r2) і `obscura` не перевірялися.
